## 为什么需要它

微信没有"只允许看当前这条视频"的开关。即使你关掉了「发现页」的视频号入口，聊天框和群聊里别人发的链接依然是一条最顺手的入口——点开看，看完往上一滑，就掉进推荐流里了。

本工具要解决的正是这一个动作：**断掉"看完这一条 → 滑到下一条"的自动惯性**，同时不打扰你正常观看。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 严格模式 | 在视频号里滑动翻页 → 立即自动退出，回到聊天界面 |
| 严格模式承诺期 | 可选 **1 天 / 7 天 / 两周 / 1 个月 / 半年**，**到期前无法在 App 内改成其它模式** |
| 限时模式 | 可自由观看 5 / 10 / 20 分钟，剩 1 分钟提醒，到点自动退出 |
| 暂停守护 | 临时关闭拦截，不用去系统设置里关服务 |
| 多条链接连续观看 | 聊天框里逐个点开不同的视频号链接都正常，**只有滑才退** |
| 拦截灵敏度可调 | 滑动 1 次（最猛）/ 2 次（推荐）/ 4 次（宽松）触发退出 |
| 返回兜底 | 部分 ROM 会吞掉返回操作，会自动补发，最多三次 |
| 常驻通知保活 | 服务前台化并常驻通知栏（显示今日拦截数），显著降低被系统回收的概率 |
| 后台保护自检 | 检测是否已加入电池优化白名单，一键跳转授权页 |
| 拦截统计 | 今日拦截次数、累计拦截次数、已守护天数 |
| 调试日志 | 主界面可查看最近 30 条事件记录，**支持一键复制**，便于排查适配问题 |

## 快速开始

### 1. 下载安装

从 [Releases](https://github.com/coopermary952-ship-it/ChannelsGuard/releases) 下载最新的 APK（形如 `ChannelsGuard-v2.2-debug.apk`），传到手机后安装。

> Android 8.0（API 26）及以上可用。安装时系统会提示"未知来源应用"，允许即可。

### 2. 开启无障碍服务（唯一必须的一步）

打开「视频号守门员」App → 点「**去开启无障碍服务**」→ 在列表里找到 **视频号守门员** → 打开开关。

不同厂家的入口略有差异，一般是：

```
系统设置 → 辅助功能 / 无障碍 → 无障碍应用 / 已安装的服务 → 视频号守门员 → 开启
```

回到 App，顶部显示 **「服务状态：运行中 ✔」** 即表示生效。（按钮会尝试直接打开本 App 的无障碍详情页，省得你在列表里找；不支持的 ROM 会回退到列表页。）

### 3. 选模式

- 想立刻见效 → **严格模式**，并选一个承诺期
- 想给自己留点额度、避免戒断反弹 → **限时模式**，选 10 分钟

完成。之后在微信里正常用就行，它会自己在后台守着。

### 4. 别再划掉后台（重要）

**把 App 从最近任务划掉，是导致失效的头号原因。** 国产 ROM（MIUI / ColorOS / OriginOS / EMUI 等）划掉卡片时不止杀进程，还会把 App 置为「强制停止」，**系统授予的无障碍服务会一起被停用**，于是只能回来重新开一次。原生 Android 不会这样。

正确做法：

1. 在最近任务里把本 App 的卡片**下拉或长按，点「锁」固定住**（各品牌手势略有差异）
2. 系统设置里给它**允许自启动 + 允许后台运行 + 关闭省电策略**
3. 点 App 里的「加入电池优化白名单」按钮，或确认它显示 ✔

做完这些，日常根本不需要再打开这个 App。状态栏那条常驻通知就是"它还活着"的信号。

> 补充一句：第三方 App **无法用代码替你打开无障碍开关**，这是 Android 的限制。所以"掉线了自动恢复"这件事做不到，只能靠不让它掉线。

## 使用说明

### 三种模式怎么选

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| **严格模式** | 已经沉迷、想立刻掐断 | 视频号内滑动翻页 → 立即退出。每条都要重新点开链接才能看 |
| **限时模式** | 想减量但不想一刀切 | 进视频号后开始倒计时，期间随便滑；剩 1 分钟提醒；到点退出 |
| **暂停守护** | 临时需要翻看视频号 | 不做任何拦截，等于关闭，但服务仍然开着，随时切回来 |

### 关于「承诺期」

开启严格模式时必须先选一个承诺期：**1 天 / 7 天 / 两周 / 1 个月 / 半年**。选定并确认后：

- 「限时模式」「暂停守护」两个选项会**置灰不可点**
- 主界面顶部显示 **「严格模式锁定中，剩余 X 天 X 小时后可更改模式」**
- 倒计时结束自动解除，届时再选一次即可继续

这不是说说而已：就算绕过界面直接改本地配置，服务层仍会在每次事件里重新判定，承诺期内一律按严格模式执行。

> ⚠️ 诚实的边界：它锁的是**这个 App 自己的设置**。你依然可以通过「关闭系统的无障碍服务」「卸载 App」「清除 App 数据」绕过。工具负责挡住惯性，最后一道防线得靠你自己那部分决心。

### 界面说明

主界面从上到下依次是：

1. **服务状态** — 是否已在系统里开启
2. **去开启无障碍服务** — 一键跳转系统设置
3. **统计数据** — 今日拦截 / 累计拦截 / 已守护天数
4. **锁定提示** — 承诺期间的剩余时间（未锁定则隐藏）
5. **守护模式** — 三种模式单选
6. **严格模式承诺期** — 勾选严格模式且未锁定时出现
7. **限时时长** — 勾选限时模式时出现
8. **拦截灵敏度** — 勾选严格模式时出现，决定滑动几次算"你在刷"
9. **画面内容变化检测** — 实验性兜底开关，默认关闭
10. **调试日志** — 最近 30 条事件记录 + 「复制调试日志」按钮

### 拦不住？三步自查

1. 打开 App 底部的**调试日志**，看有没有 `滑动 ΔY=… 第n次` 这样的记录。
2. **有记录但没退出** → 说明事件能收到，只是没到阈值。把「拦截灵敏度」调到 **1 次最猛**。
3. **完全没有记录** → 说明你手机上的微信压根不发出滚动事件。此时勾选 **画面内容变化检测**（实验功能）：它改成定期比对画面里的可见文字，文字整体变了就判定换了视频并退出。

> 入口提示：消失的 12 小时、3 天选项已按需求下线，现在**最短承诺期就是 1 天**。

## 工作原理

全程只用系统标准的 `AccessibilityService`，没有任何注入或 Hook。

```
                  ┌──────────────────────────────────────┐
  你在微信视频号里  │  微信窗口事件 (typeWindowStateChanged) │
  滑动视频      →  │  类名小写包含 "finder" → 判定为视频号    │
                  └──────────────┬───────────────────────┘
                                 │
                  ┌──────────────▼───────────────────────┐
                  │  滚动事件 (typeViewScrolled)          │
                  │  进入界面 2 秒内的初始化滚动 → 忽略      │
                  │  累计滚动次数达到灵敏度阈值 → 判定在刷    │
                  │  默认阈值 2 次，可在 App 内调 1/2/4     │
                  └──────────────┬───────────────────────┘
                                 │
                  ┌──────────────▼───────────────────────┐
                  │  performGlobalAction(GLOBAL_ACTION_BACK) │
                  │  0.7s / 1.5s 后复查，仍在视频号则补发   │
                  │  + Toast 提示 + 拦截计数 +1            │
                  └──────────────────────────────────────┘
```

几个关键参数（都在 `GuardService.java` 顶部，可自行调）：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `ENTER_GRACE_MS` | 2000 | 刚进界面的初始化滚动不介入 |
| `KEY_SENSITIVITY` | 2 | 累计滑动几次触发退出（App 内可改） |
| `BLOCK_DEBOUNCE_MS` | 1200 | 两次拦截的最小间隔，防止连退到底 |
| `BACK_RETRY_DELAYS` | 0 / 700 / 1500ms | 返回动作的补发时机，对付吞掉返回的 ROM |

**为什么从"必须 1 秒内连续 4 次"改成"累计计数"？**
v2.1 为了解决"点开第二个链接被误退出"，把判定收紧成「1 秒窗口内连续滚动 ≥4 次」。这在真机上不成立：你滑一次只产生 1~2 个事件，而且中间隔着几秒的观看时间，计数器早被窗口清零，结果连续刷五六个视频一次都拦不住。

本版改为：**进入视频号后累计计数，达到阈值就退**（阈值默认 2，可在界面调）。配合保留的 2 秒进入宽限，点开第二个链接时微信的恢复滚动（通常只有 1 次）依然不会误触发。

## 已知限制

这些都是真实的、尚未解决的问题，先说清楚：

1. **评论区快速滑动会误触发退出**
   严格模式下尚未区分主视频流和评论区，翻评论翻快了也会被退出。需要真机逐个界面抓 `event.getSource()` 的类名才能精确区分。

2. **限时模式的倒计时可能被系统回收**
   倒计时跑在服务进程里的 `Handler` 上，被省电策略杀掉后会重新计时。彻底解决要改前台服务 + `AlarmManager` 兜底。

3. **微信大版本更新后可能识别失效**
   "包含 `finder` 的类名"是微信内部实现，没有官方承诺。哪天突然不灵了，看一眼 App 里的调试日志就能确认是没进入、还是进了没拦。

4. **无法对抗有意的绕过**
   自己去关无障碍服务、卸载 App、清 App 数据都能解开。这是 Android 的边界，不是这个 App 的疏漏。

5. **仅在包名 `com.tencent.mm`（微信）内生效**

6. **实验功能「画面内容变化检测」可能误判**
   它靠比对界面可见文字判断是否换了视频，点赞数跳动、评论自动加载都可能触发误退出。因此定位是"兜底"，默认关闭，只在确认收不到滚动事件时才建议开启。
   其它短视频 App 不在白名单里，也不打算支持。

## 常见问题

**Q：会不会影响微信的其它功能？**
A：服务只订阅微信这一个包名的两类事件（窗口切换、视图滚动），且只在判定为视频号界面时才介入。点赞、评论输入、暂停播放这些都不产生滚动事件，不会触发拦截——但快速滑动评论区会被误判（见已知限制 1）。

**Q：会不会被微信封号？**
A：常规模式下它没有读取界面文字、没有篡改微信数据、没有注入任何代码，只做两件事：读系统公开的窗口/滚动事件，调用系统标准的"返回"动作。这与常见的无障碍工具类 App 原理一致。若开启实验功能，会多一个"读当前界面可见文字做比对"的动作，但仍不碰聊天数据、不联网。无障碍类工具本身存在平台态度上的不确定性，请自行判断风险，用也在自己的设备上自用。

**Q：为什么我划掉后台之后，拦截就失效了？**
A：国产 ROM 划掉卡片时会把 App 置为「强制停止」，Android 规定 force-stop 会停用该应用的所有服务，**包括系统授予的无障碍服务**，所以只能回设置再开一次。这是厂商行为，App 改不了。缓解办法见 [第 4 步](#4-别再划掉后台重要)：锁定最近任务卡片 + 加电池白名单 + 允许后台运行。另外，第三方 App 无权代你打开无障碍开关，所以做不了"掉线自动恢复"。

**Q：状态栏那条通知能关掉吗？**
A：可以，但**不建议**。那条通知是前台服务的凭证，进程优先级因此提高，被系统回收的概率明显下降。隐藏通知不等于进程还活着——很多 ROM 恰恰是先杀没有前台通知的后台进程。
A：先看 App 底部的调试日志做三步自查（见 [拦不住？三步自查](#拦不住三步自查)）。大概率把灵敏度调到「1 次最猛」就好使。

**Q：能限制"每天总共看多久"吗？**
A：暂时不能。目前只能限制"单次不退出的时长"和"干脆不让滑"。每日总额度在路线图里。

**Q：为什么不上传我的使用数据到云端？**
A：因为根本没联网，见下方隐私说明。

**Q：手机换了 / App 重装，统计还在吗？**
A：统计存在本地 SharedPreferences，且 Manifest 里关闭了 `allowBackup`，卸载即清空。

## 自己编译

环境要求：**Android 8.0+ 设备**、**JDK 17+**、**Android SDK**。

```bash
git clone https://github.com/coopermary952-ship-it/ChannelsGuard.git
cd ChannelsGuard

# 把本机 SDK 路径写进 local.properties
echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties

./gradlew assembleDebug
```

产物在 `app/build/outputs/apk/debug/`，同时会自动复制一份带版本号的文件到 `dist/ChannelsGuard-v<version>-debug.apk`。

项目结构：

```
ChannelsGuard/
├── app/src/main/
│   ├── java/com/xingyuan/channelsguard/
│   │   ├── GuardService.java   # 核心：界面判定 + 滑动识别 + 拦截 + 统计
│   │   └── MainActivity.java   # 界面：服务状态、模式选择、承诺期、统计、日志
│   └── res/xml/accessibility_service_config.xml  # 无障碍服务订阅配置
└── dist/                       # 编译产物（已 gitignore）
```

## 隐私说明

- **不联网**：Manifest 里没有任何网络权限，代码里也没有任何网络请求，物理上无法上传数据。
- **默认不看界面文字**：常规拦截只读取"发生了滚动"这个**系统级事件信号**，不读取任何文本。
- **⚠️ 唯一的例外，且默认关闭**：实验功能「画面内容变化检测」开启后，会每隔 800ms 遍历当前界面的可见文字，在**内存里**拼成指纹与上一次比对，用于判断是否换了视频。指纹只在内存里存在，**不写进任何文件、不进 SharedPreferences、不联网**。你不勾选它，这段代码一行都不会跑。
- **只在微信生效**：无障碍服务配置里写死了 `android:packageNames="com.tencent.mm"`，其它 App 的事件一概不收。
- **数据全在本地**：模式、承诺期、拦截统计、调试日志都存在 App 私有的 `SharedPreferences`，且 `allowBackup="false"`，卸载即清零。
- **无第三方 SDK**：整个项目只依赖 Android SDK，没有统计、没有推送、没有广告。
