# 视频号守门员 ChannelsGuard

> 一句话：**点开视频号链接可以看，往下滑就自动退出。**
>
> 一个 Android 无障碍服务小工具，专门治"本来只想看一条，结果刷了两小时"。

不需要 root、不需要 Xposed、不改微信、不联网、不申请任何运行时权限。

**English**: A minimal Android accessibility service that auto-exits WeChat Channels (视频号) when you try to swipe to the next video — so you only watch the one you tapped.

## 为什么需要它

微信没有"只允许看当前这条视频"的开关。即使你关掉了「发现页」的视频号入口，聊天框和群聊里别人发的链接依然是一条最顺手的入口——点开看，看完往上一滑，就掉进推荐流里了。

本工具要解决的正是这一个动作：**断掉"看完这一条 → 滑到下一条"的自动惯性**，同时不打扰你正常观看。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 严格模式 | 在视频号里滑动翻页 → 立即自动退出，回到聊天界面 |
| 严格模式承诺期 | 可选 12 小时 / 1 天 / 3 天 / 7 天，**到期前无法在 App 内改成其它模式** |
| 限时模式 | 可自由观看 5 / 10 / 20 分钟，剩 1 分钟提醒，到点自动退出 |
| 暂停守护 | 临时关闭拦截，不用去系统设置里关服务 |
| 多条链接连续观看 | 聊天框里逐个点开不同的视频号链接都正常，**只有滑才退** |
| 拦截统计 | 今日拦截次数、累计拦截次数、已守护天数 |
| 调试日志 | 主界面可查看最近 30 条进入/离开/拦截记录，便于排查适配问题 |

## 快速开始

### 1. 下载安装

从 [Releases](https://github.com/coopermary952-ship-it/ChannelsGuard/releases) 下载最新的 APK（形如 `ChannelsGuard-v2.2-debug.apk`），传到手机后安装。

> Android 8.0（API 26）及以上可用。安装时系统会提示"未知来源应用"，允许即可。

### 2. 开启无障碍服务（唯一必须的一步）

打开「视频号守门员」App → 点「**去开启无障碍服务**」→ 在列表里找到 **视频号守门员** → 打开开关。

不同厂家的入口略有差异，一般是：

```
系统设置 → 辅助功能 / 无障碍 → 无障碍应用 / 已安装的服务 → 视频号守门员 → 开启
```

回到 App，顶部显示 **「服务状态：运行中 ✔」** 即表示生效。

### 3. 选模式

- 想立刻见效 → **严格模式**，并选一个承诺期
- 想给自己留点额度、避免戒断反弹 → **限时模式**，选 10 分钟

完成。之后在微信里正常用就行，它会自己在后台守着。

## 使用说明

### 三种模式怎么选

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| **严格模式** | 已经沉迷、想立刻掐断 | 视频号内滑动翻页 → 立即退出。每条都要重新点开链接才能看 |
| **限时模式** | 想减量但不想一刀切 | 进视频号后开始倒计时，期间随便滑；剩 1 分钟提醒；到点退出 |
| **暂停守护** | 临时需要翻看视频号 | 不做任何拦截，等于关闭，但服务仍然开着，随时切回来 |

### 关于「承诺期」

开启严格模式时必须先选一个承诺期：**12 小时 / 1 天 / 3 天 / 7 天**。选定并确认后：

- 「限时模式」「暂停守护」两个选项会**置灰不可点**
- 主界面顶部显示 **「严格模式锁定中，剩余 X 天 X 小时后可更改模式」**
- 倒计时结束自动解除，届时再选一次即可继续

这不是说说而已：就算绕过界面直接改本地配置，服务层仍会在每次事件里重新判定，承诺期内一律按严格模式执行。

> ⚠️ 诚实的边界：它锁的是**这个 App 自己的设置**。你依然可以通过「关闭系统的无障碍服务」「卸载 App」「清除 App 数据」绕过。工具负责挡住惯性，最后一道防线得靠你自己那部分决心。

### 界面说明

主界面从上到下依次是：

1. **服务状态** — 是否已在系统里开启
2. **去开启无障碍服务** — 一键跳转系统设置
3. **统计数据** — 今日拦截 / 累计拦截 / 已守护天数
4. **锁定提示** — 承诺期间的剩余时间（未锁定则隐藏）
5. **守护模式** — 三种模式单选
6. **严格模式承诺期** — 勾选严格模式且未锁定时出现
7. **限时时长** — 勾选限时模式时出现
8. **调试日志** — 最近 30 条事件记录

## 工作原理

全程只用系统标准的 `AccessibilityService`，没有任何注入或 Hook。

```
                  ┌──────────────────────────────────────┐
  你在微信视频号里  │  微信窗口事件 (typeWindowStateChanged) │
  滑动视频      →  │  类名小写包含 "finder" → 判定为视频号    │
                  └──────────────┬───────────────────────┘
                                 │
                  ┌──────────────▼───────────────────────┐
                  │  滚动事件 (typeViewScrolled)          │
                  │  进入界面 2 秒内的初始化滚动 → 忽略      │
                  │  1 秒内连续滚动 ≥ 4 次 → 判定为主动甩动  │
                  │  1 秒内滚动 1~2 次 → 系统恢复状态，忽略  │
                  └──────────────┬───────────────────────┘
                                 │
                  ┌──────────────▼───────────────────────┐
                  │  performGlobalAction(GLOBAL_ACTION_BACK) │
                  │  + Toast 提示 + 拦截计数 +1            │
                  └──────────────────────────────────────┘
```

几个关键参数（都在 `GuardService.java` 顶部，可自行调）：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `ENTER_GRACE_MS` | 2000 | 刚进界面的初始化滚动不介入 |
| `FLING_THRESHOLD` | 4 | 1 秒内滚动达到几次算"你在主动刷" |
| `FLING_WINDOW_MS` | 1000 | 甩动判定的统计窗口 |
| `BLOCK_DEBOUNCE_MS` | 1000 | 两次拦截的最小间隔，防止连退到底 |

**为什么用"连续滚动次数"而不是"时间宽限"来判断？**
早期版本用"进入后 2 秒内的滑动不拦截"，结果点开**第二个**视频号链接时被误退出——因为微信恢复上次浏览位置产生的滚动事件正好落在宽限期之外。改成识别甩动手势后，系统自己的恢复滚动（1~2 次）不会触发，而人手甩动通常 1 秒内会产生 4 次以上连续滚动，两者能可靠区分。

## 已知限制

这些都是真实的、尚未解决的问题，先说清楚：

1. **评论区快速滑动会误触发退出**
   严格模式下尚未区分主视频流和评论区，翻评论翻快了也会被退出。需要真机逐个界面抓 `event.getSource()` 的类名才能精确区分。

2. **限时模式的倒计时可能被系统回收**
   倒计时跑在服务进程里的 `Handler` 上，被省电策略杀掉后会重新计时。彻底解决要改前台服务 + `AlarmManager` 兜底。

3. **微信大版本更新后可能识别失效**
   "包含 `finder` 的类名"是微信内部实现，没有官方承诺。哪天突然不灵了，看一眼 App 里的调试日志就能确认是没进入、还是进了没拦。

4. **无法对抗有意的绕过**
   自己去关无障碍服务、卸载 App、清 App 数据都能解开。这是 Android 的边界，不是这个 App 的疏漏。

5. **仅在包名 `com.tencent.mm`（微信）内生效**
   其它短视频 App 不在白名单里，也不打算支持。

## 常见问题

**Q：会不会影响微信的其它功能？**
A：服务只订阅微信这一个包名的两类事件（窗口切换、视图滚动），且只在判定为视频号界面时才介入。点赞、评论输入、暂停播放这些都不产生滚动事件，不会触发拦截——但快速滑动评论区会被误判（见已知限制 1）。

**Q：会不会被微信封号？**
A：它没有读取聊天内容、没有篡改微信数据、没有注入任何代码，只做两件事：读系统公开的窗口/滚动事件，调用系统标准的"返回"动作。这与常见的无障碍工具类 App 原理一致。但无障碍类工具本身存在平台态度上的不确定性，请自行判断风险，用也在自己的设备上自用。

**Q：能限制"每天总共看多久"吗？**
A：暂时不能。目前只能限制"单次不退出的时长"和"干脆不让滑"。每日总额度在路线图里。

**Q：为什么不上传我的使用数据到云端？**
A：因为根本没联网，见下方隐私说明。

**Q：手机换了 / App 重装，统计还在吗？**
A：统计存在本地 SharedPreferences，且 Manifest 里关闭了 `allowBackup`，卸载即清空。

## 自己编译

环境要求：**Android 8.0+ 设备**、**JDK 17+**、**Android SDK**。

```bash
git clone https://github.com/coopermary952-ship-it/ChannelsGuard.git
cd ChannelsGuard

# 把本机 SDK 路径写进 local.properties
echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties

./gradlew assembleDebug
```

产物在 `app/build/outputs/apk/debug/`，同时会自动复制一份带版本号的文件到 `dist/ChannelsGuard-v<version>-debug.apk`。

项目结构：

```
ChannelsGuard/
├── app/src/main/
│   ├── java/com/xingyuan/channelsguard/
│   │   ├── GuardService.java   # 核心：界面判定 + 滑动识别 + 拦截 + 统计
│   │   └── MainActivity.java   # 界面：服务状态、模式选择、承诺期、统计、日志
│   └── res/xml/accessibility_service_config.xml  # 无障碍服务订阅配置
└── dist/                       # 编译产物（已 gitignore）
```

## 隐私说明

- **不联网**：Manifest 里没有任何网络权限，代码里也沒有任何网络请求，物理上无法上传数据。
- **不看聊天内容**：只读取窗口切换与滚动这两类**系统级**事件，不读取消息正文、联系人、图片、视频内容。
- **只在微信生效**：无障碍服务配置里写死了 `android:packageNames="com.tencent.mm"`，其它 App 的事件一概不收。
- **数据全在本地**：模式、承诺期、拦截统计、调试日志都存在 App 私有的 `SharedPreferences`，且 `allowBackup="false"`，卸载即清零。
- **无第三方 SDK**：整个项目只依赖 Android SDK，没有统计、没有推送、没有广告。
